# AGENTS.md — правила для ассистента (Sektor.TurnBased)

Этот файл автоматически читается ассистентом при работе в проекте. См. также `docs/*.md` — подробное описание принципов и решений.

## Сборка и тесты

- Сборка: `dotnet build Sektor.TurnBased.slnx` — **обязательно 0 предупреждений**.
- Тесты: `dotnet test Sektor.TurnBased.slnx` (xunit). Перед завершением задачи всегда запускай обе команды.
- Если что-то не компилируется или падает — не считай задачу выполненной.

## Структура решения

- `src/Core/Sektor.TurnBased.Core.Abstractions/` — контракты ядра: `IGameState`, `IGameCommand`, `PhaseTransition`, `Result`, `Result<T>`.
- `src/Core/Sektor.TurnBased.Core/` — ядро: `GamePipeline`, `IGamePhase`, `GameContext`, `GameEventBus`, `VisualQueue`, `VisualEvent`, `GameLog`, `ContentRegistry`, `DeterministicRng`.
- `src/Battle/Sektor.TurnBased.Battle/` — первая игра на ядре: `Model/` (данные-ресурсы), `Effects/` (эффекты и прекондиции), `Rules/` (порядок ходов, условия победы), `Phases/`, `Content/` (каталог + валидация), `Events/`, `Commands/`, фасад `BattleEngine` + `BattleAi` + `BattleExecutor`.
- `src/Dialog/Sektor.TurnBased.Dialog/` — вторая игра на ядре: фазовый диалог/квест с ветвлениями по флагам и вложенным диалогом через `CreateChildPipeline` (см. `docs/dialog.md`). `Model/` (узлы/варианты/состояние), `Content/` (каталог + валидация), `Phases/`, `Events/`, `Commands/`, фасад `DialogEngine` + `DialogEventSink`.
- `tests/` — `Sektor.TurnBased.Core.Tests` (24 теста), `Sektor.TurnBased.Battle.Tests` (48 тестов), `Sektor.TurnBased.Dialog.Tests` (21 тест).

## Конвенции кода

- net8.0, `Nullable`, `ImplicitUsings`, современный C# (records, паттерн-матчинг, init-only).
- **XML-доки на всех public-типах и public-членах** — обязательны.
- Один публичный тип на файл; файл назван по типу.
- records для DTO/данных; приватные сеттеры; состояние меняется только через валидирующие методы.
- **Строковые Id вместо enum** (типы событий, эффектов, фаз, ресурсов).
- **Запрещены enum/switch/if-else для разделения поведения** — только полиморфизм (стратегии, состояния, данные-ресурсы через `ContentRegistry`).
- Ошибки через `Result`/`Result<T>`, **ядро никогда не бросает исключений** (подписчики шины изолируются).
- Зависимости через конструктор (DI), запрещён хардкод-`new` внутри логики.
- Ядро (`src/Core`) не знает про конкретные игры; игры — потребители ядра.

## Инварианты

- **Детерминизм**: случайность только через `DeterministicRng` (seed из `GameContext`); одинаковый seed → одинаковый лог и визуальные события.
- **Визуал только через `VisualQueue`**: `VisualEvent` — immutable-снимок (строковый тип, Id акторов, значение, payload), без ссылок на объекты игры.
- События не поднимаются из обработчиков `GameEventBus` (нет каскадов внутри обработчиков).
- Контент валидируется на загрузке (`ContentValidator`), а не в рантайме.

## Что не делать

- Не создавай анаемичную модель данных (только get/set без логики).
- Не смешивай слои: домен не знает про UI/консоль/БД.
- Не плоди лишние абстракции — соблюдай баланс YAGNI/KISS; код должен читаться сверху вниз.
- Не добавляй комментарии-пояснения в код, если они не запрошены.
- Не используй кортежи (Tuple), создавай классы.
- Не используй словари (Dictionary), если это не повышает производительность, создавай классы.
- Не создавай больше одного класса в одном файле.
