# Принципы разработки

Коротко: что мы считаем правильным и почему. Детали реализации — в `architecture.md` и `battle.md`, история решений — в `decisions.md`.

## Стиль

- **SOLID**: одна ответственность на класс, расширение через новые классы (OCP), зависимость от абстракций.
- **Баланс YAGNI/KISS**: не усложняй структуру без необходимости. Простая стратегия лучше трёхклассного «Посетителя». Код читается сверху вниз.
- **Современный C#**: records для данных, паттерн-матчинг, init-only, nullable reference types.

## Поведение vs данные

- **Данные-ресурсы**: типы поведения и их параметры — данные (определения в `ContentRegistry`), а не код-ветвление. Расширение = добавление данных/классов, а не правка switch.
- **Запрещены enum и switch/if-else для разделения бизнес-логики.** Вместо этого — полиморфизм, «Стратегия», «Состояние», Enumeration Class.
- **Строковые Id** вместо enum: типы событий, эффектов, фаз, ресурсов идентифицируются строкой. Плюс валидация на загрузке, чтобы опечатки ловились сразу.
- **Разделяй структуры данных (DTO/контейнеры) и поведение (сервисы/стратегии).**
- **Не создавай анаемичную модель**: сущность сама управляет своим состоянием и инкапсулирует правила; приватные сеттеры, изменение только через валидирующие методы.

## Слои и зависимости

- **Слои не смешиваются**: домен не зависит от UI, консоли, БД, внешних библиотек.
- Зависимости запрашиваются через интерфейсы в конструкторе (Dependency Inversion). Хардкод-`new` внутри логики запрещён.
- **Ядро (`src/Core`) — это фреймворк пошаговых игр без привязки к конкретной игре.** Игры (например, `Battle`) — потребители ядра.

## Ошибки и случайность

- **Ошибки через `Result`/`Result<T>`**, а не исключения. Ядро никогда не бросает.
- **Детерминизм**: вся случайность через `DeterministicRng`; одинаковый seed → одинаковый результат. Это нужно для тестов, реплеев и воспроизводимых симуляций.
- Контент валидируется на загрузке, а не в рантайме.

## UI и события

- Домен сообщает о происходящем **событиями**, а не напрямую вызывает UI.
- Ядро изменяет состояние мгновенно, а для анимаций пишет **снимки в `VisualQueue`**; UI читает очередь последовательно.
